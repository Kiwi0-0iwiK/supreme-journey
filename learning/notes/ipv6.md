# IPv6 實戰筆記 — 從「有線拿不到位址」開始

> 狀態：使用中
> 動機：想讓朋友跟我的電腦直連，不要繞中繼伺服器。查到最後發現最乾淨的路是 IPv6，然後才發現我家的有線根本沒有 IPv6

這份接在[家用網路基礎](networking.md)後面。那份的最後一章只用十行帶過「IPv6 不需要 NAT」，這份是真的動手之後補上的細節。範例位址一律用文件專用的 `2001:db8::/32`。

---

## 一、為什麼突然在乎 IPv6

兩台都躲在 NAT 後面的電腦要直連，得靠打洞（見家用網路基礎第十一章）。打洞成不成功，看的是 NAT 的脾氣：

```
   好打的 NAT：同一個內部埠，對誰都用同一個外部埠
               → 協調伺服器看到的埠，對方也能用

   難打的 NAT：每換一個目的地，就換一個外部埠
               → 協調伺服器看到的埠，對別人無效
               → 打洞失敗，退回中繼
```

我家是後者。Tailscale 的 `netcheck` 會直接告訴你：`MappingVariesByDestIP: true`。

IPv6 把整個問題拿掉。**每台裝置都有全球唯一的位址，沒有 NAT，也就沒有洞要打。**

---

## 二、位址長什麼樣

一張網卡上通常同時有好幾個 IPv6 位址，這是正常的。

| 種類 | 開頭 | 範圍 | 用途 |
|---|---|---|---|
| **Link-local** | `fe80::` | 只在同一段線路上有效，路由器不轉送 | 跟隔壁鄰居講話、當預設閘道的位址 |
| **全域** | `2` 或 `3` 開頭 | 全世界 | 真正用來上網 |

```
   2001:db8:1234:5678 : a1b2:c3d4:e5f6:7890
   └──── 前綴 /64 ────┘ └──── 介面識別 ────┘
     ISP 配給你家的         這台裝置自己決定的
     全家共用同一段
```

**只有 `fe80::` 沒有全域位址，就等於沒有 IPv6 可以上網。** 這是最容易看漏的一點：`ipconfig` 裡明明有一行 IPv6，但那行是每張網卡都會自動產生的 link-local，不代表什麼。

全域位址通常還會有兩個：一個固定的，一個定期更換的**臨時位址**。對外連線預設用臨時的，避免別人靠位址後半段長期追蹤同一台裝置。

---

## 三、位址怎麼來：不需要 DHCP

IPv4 要有人發號（DHCP）。IPv6 的主流做法是**自己組**，叫 SLAAC。

```
   裝置                                        路由器
     │                                            │
     │  ①「這條線上有路由器嗎？」（多播）          │
     ├───────────────────────────────────────────▶│
     │                                            │
     │  ②「有。前綴是 2001:db8:1234:5678::/64，    │
     │      預設閘道是我，MTU 是 1492，             │
     │      DNS 用這幾台」（多播）                  │
     │◀───────────────────────────────────────────┤
     │                                            │
     │  ③ 前綴 + 自己產生的後 64 位 = 完整位址      │
     │     不用跟任何人登記                         │
```

第 ② 步那則訊息叫**路由器通告（RA）**。它一次給了四樣東西：前綴、預設閘道、MTU、DNS。

**整個自動設定都靠 RA 這一則多播訊息。** 中間任何一台設備沒把它送到，裝置就只剩 `fe80::`，而且不會有任何錯誤訊息。

IPv6 也沒有 ARP，找鄰居的 MAC 改用**鄰居探索（NDP）**，一樣跑在 ICMPv6 上。所以 IPv6 的世界裡**不能把 ICMP 全部擋掉**，擋了連位址都拿不到。路由器上那種「只過濾不必要的 ICMPv6」的選項是對的做法。

---

## 四、沒有 NAT 意味著什麼

我手動設好之後，去問外部網站「你看到我是誰」，回來的就是**我電腦自己的位址**。在 IPv4 的世界裡這件事不會發生，你看到的永遠是路由器的位址。

| | IPv4 + NAT | IPv6 |
|---|---|---|
| 外面看到的位址 | 路由器的 | **裝置自己的** |
| 別人要連進來 | 要設連接埠轉發 | 位址本來就可達，只看防火牆放不放 |
| 兩台裝置直連 | 要打洞，可能失敗 | 直接連 |

「位址本來就可達」聽起來很危險，實際上擋在前面的是**防火牆**：路由器預設不放行從外面主動進來的連線，電腦自己也有一層。差別只在於這次是防火牆名正言順地在做這件事，不是 NAT 順便擋到。

## 五、案例：有 `fe80::` 沒有全域位址

我的桌機接在一台**被我降級成交換器的舊路由器**後面，再接到 ISP 的閘道。有線只有 link-local。

### 排查順序

| 步驟 | 做法 | 我得到的結果 |
|---|---|---|
| 1. ISP 的閘道有沒有發 | 看管理頁的 IPv6 設定 | 有開，LAN 端有全域 /64 |
| 2. 繞過中間設備 | 同一台電腦改用 Wi-Fi 直連閘道 | **馬上拿到全域位址** |
| 3. 中間設備到底擋了什麼 | 從有線 ping 閘道的 IPv6 位址，查鄰居表 | **ping 通、鄰居表查得到** |

第 2 步是對照實驗：同一台電腦、同一個閘道，只差有沒有經過那台舊路由器。

第 3 步推翻了我原本的結論。我一開始寫下「舊路由器把 IPv6 擋掉了」，但一般封包和鄰居探索其實都會過，**缺的只有自動設定那一則通告的效果**。

| | 性質 |
|---|---|
| 經過舊路由器就拿不到全域位址，繞過就拿得到 | 實測 |
| 一般 IPv6 封包與鄰居探索會通過它 | 實測 |
| 原因是它沒有轉送 RA 的多播 | **已確認**。後來抓封包，經過它時有線網卡完全收不到 RA；拿掉它、兩條線直接用對接頭接起來之後，**自動設定立刻恢復**，MTU 也變成通告裡的 1492 |

### 過程中的三個誤判

1. **以為 IPv6 已經通了。** 當時 Wi-Fi 連著手機熱點，那個全域位址是行動網路給的。**量測前先確認只剩你要量的那條線在線上**
2. **以為 ISP 的閘道沒開 IPv6。** 沒看管理頁就先下結論
3. **「擋掉了」說得太重。** 多測一步才知道只是自動設定沒生效，而這個差別決定了能不能手動補救

## 六、手動設定：可行的過渡方案

既然一般封包過得去，就把 RA 本來會告訴我的東西自己填上：一個位址、一條預設路由。

```powershell
New-NetIPAddress -InterfaceAlias <網卡名稱> -IPAddress 2001:db8:1234:5678::108 -PrefixLength 64
New-NetRoute -InterfaceAlias <網卡名稱> -DestinationPrefix ::/0 -NextHop fe80::<閘道的後半段>
```

**預設閘道填的是 link-local 位址**，不是全域位址。這是 IPv6 的慣例：下一跳只需要在同一段線上找得到，而且 link-local 不會因為 ISP 換前綴而改變。

### 這樣做的代價

- **家用線路的前綴通常是浮動的。** 重新撥號可能換一組，手動填的位址就失效。而且它是**安靜地壞掉**：程式會自動退回 IPv4，你只會覺得「怎麼又變慢了」
- **MTU 沒人告訴你。** RA 會帶 MTU（PPPoE 線路是 1492），手動設定的介面維持預設 1500。我實測 1492 的封包會過、1500 不會，但作業系統的路徑 MTU 探索有接手，TCP 沒出問題
- **重開機後還在不在**要自己確認

所以它只是過渡。根本解是把那台不轉送通告的設備換掉或拿掉，我後來用一個不插電的 RJ45 對接頭把它拿掉了。

**拿掉之後記得移除手動那組，而且要預期會斷一下。** 我移除前發現系統裡的 IPv6 預設路由只有手動那一條，RA 沒有另外裝自己的。刪掉手動路由後，IPv6 斷了好幾分鐘，直到路由器下一次重送通告，預設路由才自己補回來。

確認的時候還有一個坑：**Windows 把通告給的路由也標成「手動」**，看標籤分不出來。要看壽命：手動加的是無限，通告給的是有限的、而且會倒數；另外手動加的會存在永久設定裡，通告給的不會。

刪位址時也別用自己打的前綴去指定，用「來源是手動」去篩選就好，不會打錯，也不會誤刪通告給的位址：

```powershell
Get-NetIPAddress -InterfaceAlias <網卡名稱> -AddressFamily IPv6 -PrefixOrigin Manual | Remove-NetIPAddress
```

全部拿掉之後去問外部網站，看到的是**臨時位址**，跟第二章講的一樣。

### 驗證清單

```powershell
# 有沒有全域位址（2 或 3 開頭）
Get-NetIPAddress -AddressFamily IPv6 | Where-Object IPAddress -match '^[23]'

# 有沒有 IPv6 預設路由
Get-NetRoute -DestinationPrefix ::/0

# 真的出得去嗎
ping -6 ipv6.google.com
tracert -6 ipv6.google.com

# Tailscale 的看法
tailscale netcheck
```

再用瀏覽器開任何一個「顯示我的 IP」的網站，看到的 IPv6 應該跟電腦上的**一模一樣**。

## 七、直連的另外兩條路

IPv6 不是唯一解。IPv4 這邊還有兩個辦法讓難打的 NAT 變好打。

### UPnP：讓程式自己叫路由器開埠

```
   程式 ──「請把外面進來的 UDP 41641 轉給我」──▶ 路由器 ──▶ 開了
```

不用登入管理頁，遊戲、視訊、BT 常靠它。

| | 開著 | 關著 |
|---|---|---|
| 方便性 | 程式自動開埠 | 要自己手動設 |
| 安全性 | **區網內任何程式都能擅自開埠**，不需要密碼。包括惡意程式和有漏洞的智慧家電 | 開哪些埠完全由你決定 |

ISP 的閘道預設多半是關的，我也維持關閉。

#### 一個沒料到的坑：已經不當路由器的設備還在回應 UPnP

那台被降級成交換器的舊路由器，**UPnP 服務還在跑**。程式跟它申請開埠，它說「好」，但它的 WAN 孔根本沒接線，這個對應是假的。

Tailscale 就這樣拿到了一個不存在的公網端點（`netcheck` 顯示 `PortMapping: UPnP`）。把那台的 UPnP 關掉之後，區網內搜尋不到任何 UPnP 裝置，欄位變回空白。

**把路由器改成交換器或 AP 時，UPnP 也要一起關**，這一步在家用網路基礎那份的三步驟裡沒有。

### 手動轉發 VPN 自己的埠

在路由器上把 Tailscale 用的 UDP 埠固定轉給那台電腦。固定轉發之後，從那個埠出去的封包永遠對應到同一個外部埠，不再隨目的地改變，等於把難打的 NAT 變成好打的。

開的是加密隧道的埠，沒有金鑰的人連不進來，比直接把遊戲埠開給全世界安全得多。

這個方案我**還沒做，效果沒有驗證**。

## 八、中繼不一定慢，看它在哪

查這整件事的起點，是朋友透過某個 mod 內建的分享功能連進來時延遲兩三百毫秒，改用 Tailscale 之後約 60 毫秒。

兩邊其實**都沒有直連，都在走中繼**。差別只在中繼伺服器的位置：

| | 中繼位置 | 實測延遲 |
|---|---|---|
| mod 內建的分享 | 新加坡 | 下限約 160 ms |
| Tailscale | 香港 | 中位數約 58 ms |

所以「走中繼」本身不是問題，**繞多遠才是**。延遲高的時候先查封包實際經過哪裡，不要直接假設是頻寬或電腦效能。
