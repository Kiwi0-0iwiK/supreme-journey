## 一、網際網路沒有核心

網際網路沒有核心。這是理解後面所有東西的前提。

### 為什麼「發電廠」的類比不成立

| | 電力系統 | 網際網路 |
|---|---|---|
| 方向 | 單向，發電廠 ▶ 用戶 | 雙向，任何一點都可以是來源或目的地 |
| 中心 | 有，發電廠 | **沒有** |
| 尋址 | 電子不帶地址，順著電位差流 | **每個封包自己帶目的地地址** |
| 壞掉會怎樣 | 發電廠停機，全區停電 | 拔掉任一節點，其他人照常通訊 |

最根本的差別：**電力是「推送」，網路是「投遞」**。電子不知道自己要去哪，網路封包知道。

### 比較好的類比：道路網加郵政

```
   沒有「中央道路工廠」
   只有路接著路，接成一張網

   你要寄包裹 ──▶ 寫上地址 ──▶ 交給最近的郵局
                                    │
                    每一站各自決定「下一站交給誰」
                                    │
                                    ▼
                              最終送達收件人
```

關鍵在於：**沒有任何一個郵局知道完整路徑**，每一站只知道「往這個方向丟會更接近」。這就是路由器在做的事。

Internet 這個字本身就是答案 —— **inter-net = 網路之間的網路**。它不是一張大網，是幾萬張獨立網路互相接起來。

### 但確實有階層

不是完全平等的網狀結構。

```
        ┌──────── Tier 1 ────────┐
        │  AT&T、NTT、Level 3…    │  彼此免費互連
        │  不用向任何人買頻寬      │  能到達全世界
        └───┬────────────────┬───┘
            │                │
     ┌──────▼─────┐   ┌──────▼─────┐
     │  Tier 2     │◀─▶│  Tier 2    │  向 Tier 1 買頻寬
     │  中華電信…   │   │            │  彼此也互相對接
     └──────┬─────┘   └────────────┘
            │
     ┌──────▼─────┐
     │  Tier 3     │  地區性 ISP，只能買
     └──────┬─────┘
            │
          你家
```

每一個這種網路叫 **AS（自治系統）**，有自己的編號。中華電信是 AS3462。

它們之間用 **BGP** 協定互相宣告：「我這裡可以到達這些網段」。鄰居收到後再轉告自己的鄰居，一層層擴散 —— **整張網路的路由表是靠口耳相傳長出來的**，沒有中央機構發布。

### 「開個 IP 和 port 就能連」需要三個前提

```
   ① 要有一個「全球可路由」的位址
        │   ← NAT 打破的就是這個
        │      192.168.x.x 在外面沒人認得
        ▼
   ② 路由要真的通得到你
        │   ← BGP 要有宣告過那段位址
        ▼
   ③ 中間沒有東西擋你
        │   ← 防火牆、NAT 沒設轉發、ISP 封鎖
        ▼
      對方連得進來
```

我開 Terraria 伺服器就是活例子：家用是**浮動**公網 IP，① 成立但會變，所以要 DDNS；② 由 ISP 自動成立；③ 要自己設連接埠轉發並放行防火牆。缺一個就不通。

### 有兩塊其實是中心化的

雖然資料傳輸去中心，但**命名與編號是階層式的**：

```
   IP 位址怎麼來的                 網域名稱怎麼來的
   ────────────────                ────────────────
        IANA                            根伺服器（.）
          │                                 │
   ┌──────┼──────┐                    ┌─────┼─────┐
  APNIC ARIN RIPE …                  .com  .tw  .org
   (亞太)(北美)(歐洲)                    │
          │                          google.com
      中華電信                        的權威伺服器
          │
        你家
```

所以更準確的說法是：

- **資料平面（怎麼傳）** → 去中心化，沒有核心
- **命名與編號（叫什麼、誰是誰）** → 階層式，有頂點

這個對比有現實後果：**很難「關掉網際網路」，但可以透過控制 DNS 和 BGP 讓一個國家對外斷線** —— 封包還在流動，只是沒人知道該往哪送。

> 一句話：網際網路是**幾萬張獨立網路用 BGP 互相告知「我能到哪裡」而自發長成的道路網**。沒有人擁有它，但地址簿（DNS）和門牌配發（IANA）是有階層的。

## 二、網路怎麼進到你家

上一章講的是外面那張網。這一章把最後一哩接進來 —— 光纖從馬路到你家牆上的孔，中間經過什麼。

### 從機房到你家

```
  電信機房（局端）
       │  OLT 設備
       ▼
  ┌─────────────── 光纖幹線 ───────────────┐
  │       埋在馬路下 / 架在電線桿上          │
  └───────────────────┬───────────────────┘
                      ▼
                分光器（Splitter）
              一條光纖分給 8~64 戶共用
                      │
       ┌──────────────┼──────────────┐
       ▼              ▼              ▼
     你家大樓       隔壁棟         對面棟
       │
       ▼
  大樓的光纖終端箱（多半在地下室或機房）
       │
       ▼
  ┌────────── 光纖拉進你家 ──────────┐
  │        這段叫 FTTH（光纖到府）    │
  └──────────────┬──────────────────┘
                 ▼
           家裡的光終端盒
                 │  一小段光纖跳線
                 ▼
           ONT（俗稱「小烏龜」）
                 │
          光訊號 ──▶ 電訊號
```

**分光器**這件事值得知道：GPON 架構下，一條主幹光纖是**多戶共用**的，用被動分光鏡分給 8 到 64 戶。所以方案上寫的「300M」是共享頻寬的上限，不是專線 —— 這也是尖峰時段可能變慢的原因之一。

### 牆壁上的網路孔不會產生網路

這點很容易誤會。牆上的孔只是一段**被動的銅線**，像延長線的插座 —— 沒接到電源端就什麼都沒有。

台灣的公寓通常長這樣：

```
   ONT（門口 / 玄關櫃）
       │  一條網路線
       ▼
   ┌────── 弱電箱 / 集線箱 ──────┐
   │   （常常就在同一個櫃子裡）   │
   │                             │
   │    可能是一台交換器          │
   │    也可能只是端子排          │
   └──┬──────┬──────┬──────┬─────┘
      ▼      ▼      ▼      ▼
    客廳   主臥   次臥   書房     ← 牆上的網路孔
```

| 弱電箱裡是什麼 | 結果 |
|---|---|
| **交換器** | 每個房間的孔都能同時上網 |
| **端子排**（只有接線端子） | 通常只有一個孔是通的，其他要手動改接 |
| **什麼都沒有** | 牆內線是一對一直通，要自己接 |

很多房子是第二或第三種 —— 這就是為什麼有人明明有網路孔卻不能用。

## 三、數據機與路由器的分工

線拉到家裡了，接下來看那台機器在做什麼。

> **先分清楚類別。** 這個領域的縮寫最容易搞混的不是意思，是**類別**：
>
> · **ISP**（中華電信）是**公司**
> · **ADSL / GPON** 是**技術**，講「怎麼傳」
> · **ONT / 路由器** 是**設備**，講「哪台機器」
>
> 所以「ADSL 跟 ONT 是不是同一種東西」這個問題本身就不成立 —— 一個是方法，一個是機器。
> 完整的縮寫對照在[附錄 C](#附錄-c英文縮寫對照表)。

### 小烏龜其實在做四件事

ISP 給的通常是**整合機**，一台裡面塞了四個角色：

```
  ┌─────────── ONT / 小烏龜 ───────────┐
  │                                    │
  │  ① 光電轉換   光訊號 ◀▶ 電訊號      │ ← 這才是 ONT 的本業
  │                                    │
  │  ② PPPoE 撥號  用帳密向 ISP 認證    │ ← 取得公網 IP
  │                                    │
  │  ③ 路由 + NAT  一個公網 IP 分給全家 │ ← 「路由器」的部分
  │                                    │
  │  ④ Wi-Fi AP    發射無線訊號         │ ← 常常是弱項
  │                                    │
  │  [LAN 1] [LAN 2] [LAN 3] [LAN 4]   │
  └────────────────────────────────────┘
```

**只有 ① 是它非做不可的事**，②③④ 都是順便。這解釋了為什麼它可以被設成橋接模式讓別台去撥號 —— 那時它就退回只做 ①。

### 這一切是怎麼演變成現在這樣的

整合機不是一開始就存在的。理解演進過程，「為什麼會有 WAN 孔」這件事會突然變得很合理。

```
① 撥接時代
   電腦 ──[56k 數據機]── 電話線
   一台電腦，還沒有「家用網路」這回事

② ADSL 時代（純橋接）
   電腦 ──[ADSL 數據機 = ATU-R]── 電話線 ──[DSLAM]── 機房
     ▲
     └─ PPPoE 撥號由電腦自己做（Windows 的「寬頻連線」）
   數據機什麼都不管，只轉換訊號；還是只能一台上網

③ 想給多台用 → IP 分享器誕生
   電腦 ┐
   電腦 ┼─[分享器]──[WAN孔]──[數據機]── 電話線
   電腦 ┘     ▲
             └─ PPPoE + NAT 改由它接手

   ★ WAN 孔就是在這一步被發明的
     它標記的是「這邊是外面，後面接的是數據機」

④ 無線普及
   分享器 + Wi-Fi = 無線寬頻分享器
   （早期分享器是純有線的，沒有天線）

⑤ 光纖時代
   ONT 取代 ADSL 數據機（ATU-R），OLT 取代 DSLAM
   介質從電話線換成光纖，角色完全一樣
   名字從「數據機 Modem」改叫「終端 Terminal」

⑥ ISP 整合（現在）
   ONT + PPPoE + 路由 NAT + Wi-Fi 全部塞進一台
       │
       └─▶ 使用者原本那台分享器變成多餘
           但大家捨不得丟，就串在後面
           → 雙重 NAT 問題開始普及

⑦ 廠商的回應
   AP 模式開關、Mesh 套組
```

第 ③ 步是關鍵：**路由器誕生的那一刻，它後面接的就是一台什麼都不做的橋接數據機。** 所以它的設計假設一直是「我是家裡唯一的路由器、我就是內外的分界線」，而 WAN 孔就是這個假設的物理化身。

到了第 ⑥ 步，這個假設第一次被打破 —— 上游忽然變成另一台完整的路由器，但機器本身不知道，還是照著老劇本做 NAT。雙重 NAT 就是這樣來的。

## 四、WAN 與 LAN 為什麼要分

上一章看到 WAN 孔是在「IP 分享器」誕生那一刻被發明的。這一章講它到底代表什麼 —— 以及為什麼這個區分讓路由器沒辦法自己判斷該不該退居二線。

> 這章會先用到 NAT 和 DHCP 兩個詞。現在只要知道 **NAT 是「共用一個對外身分」、DHCP 是「自動發門牌」** 就夠了，正式的說明在第六、八章。

先問一個問題：為什麼路由器不乾脆把所有孔都做成一樣的？

**因為廠商不知道你會把它放在哪裡。**

一台家用路由器出廠時，唯一合理的假設是：「有人買了我，插上數據機，我後面接著整個家。」

在這個假設下，WAN/LAN 的分野是**必要**的：

```
  ┌──────────────── 路由器 ────────────────┐
  │                                        │
  │   [WAN 孔]                  [LAN 孔]   │
  │   「外面」                   「裡面」    │
  │   不受信任                   受信任      │
  │   做 NAT                    自由互通     │
  │   擋住主動連入                發 DHCP    │
  │                                        │
  └────────────────────────────────────────┘
           ▲                        ▲
      接數據機                  接你的裝置
```

這不只是位址的差別，更是**信任邊界** —— 路由器的防火牆規則建立在「WAN 是敵區、LAN 是友軍」之上。拿掉這個區分，它就不知道該擋誰。

而且 NAT + DHCP + 防火牆全部預設開啟，是為了**開箱即用**：買回家插上就能上網，不用懂任何東西。這對 99% 的使用者是正確的預設值。

## 五、當你需要第二台

加第二台路由器有兩個常見原因，一個是位置，一個是歷史。

### 位置：ONT 搬不動

**ONT 的位置由光纖進線點決定，不能隨便搬。** 光纖有彎折半徑限制，也不像網路線可以隨意延長。於是它常常被塞在玄關櫃、配電箱這種對無線訊號最不利的地方，而且不少機型連外接天線都沒有。

結果就是：訊號源的位置由施工決定，不是由你住在哪決定。

「把訊號帶到人待的地方」因此成為唯一解，差別只在用什麼方式帶。

### 歷史：以前本來就要自己買

上一節講的是**位置**（ONT 被施工釘死在訊號最差的地方），這一節講的是**歷史**。

早期 ISP 只給數據機（純轉換訊號），所以必須自備路由器。現在 ISP 直接給你有 Wi-Fi 的整合機，本身就是完整路由器 —— 於是自己那台的**路由功能變成多餘**，但**交換器和 AP 功能還很有用**。

### Mesh / 全屋通是什麼

ISP 推的「全屋通」之類的加值服務，本質就是 **Mesh Wi-Fi**：

```
   ONT（唯一的路由器）
       │
       ├── Mesh 節點 A（客廳）
       ├── Mesh 節點 B（主臥）
       └── Mesh 節點 C（書房）

   三個節點都是 AP，不是路由器
   全部橋接到 ONT 的同一個網段
```

**重點：加了 mesh 之後，家裡仍然只有一個路由器。** 節點不做 NAT、不發 DHCP，只是把無線訊號接力出去。整個家維持一個網段、一層 NAT —— 也就是本文後面會講的理想狀態。

自己拿一台舊路由器改成 AP，做的是同一件事，差別在：

| | Mesh 套組 | 自己改一台舊路由器 |
|---|---|---|
| 設定 | 插上自動配對 | 手動關 DHCP、改 IP、搬線 |
| 漫遊 | 同一 SSID，走動時自動切換 | 要自己把 SSID 密碼設成一樣 |
| 節點間連線 | 常是無線回程 | 通常有線回程 |
| 費用 | 月租 | 0 |

**無縫漫遊**是 mesh 真正的賣點：所有節點同一個 SSID，手機移動時自動切到最強的節點。如果只是各開各的 SSID，手機會死抱著原本那個不放，直到訊號爛到斷線才換。

自己做也能達到八成 —— 把第二台的 SSID 和密碼設成跟主機**完全一樣**，手機就當成同一個網路。切換不如真 mesh 平順（少了 802.11k/v/r 那套協調機制），但日常差異不大。記得**頻道要錯開**，2.4GHz 選 1 / 6 / 11 這三個不重疊的，否則兩台互相干擾反而更慢。

### 有線回程贏過無線回程

Mesh 最大的弱點是**無線回程** —— 節點之間靠 Wi-Fi 互連，會吃掉一半以上的頻寬，距離越遠衰減越嚴重。

如果你的第二台是用網路線接回主機的，那叫**有線回程**，品質遠勝無線回程。所以在已經有牆內網路線的房子裡，自己接一台 AP 往往比租 mesh 還好用，成本也低得多。

### 廠商其實知道這很常見

現在中高階路由器幾乎都有「**AP 模式**」或「**橋接模式**」開關，按下去就自動關 NAT、關 DHCP、把 WAN 孔併入交換器 —— 就是把手動那三件事包成一鍵。

老機器沒有的話就手動做：

```
1. 關閉 DHCP 伺服器
2. LAN IP 改成上游網段內、DHCP 池以外的位址
3. 上游的線插 LAN 孔，WAN 孔空著
```

---

## 六、DHCP — 誰發門牌

**自動發身分證的服務。**

每台上網的裝置都需要一個 IP 當門牌。沒有 DHCP 的話每台都要手動指定，而且要自己記住哪些號碼被用掉了，不然撞號。

流程是四步握手：

```
  裝置                                      DHCP 伺服器
    │                                            │
    │  ①「有人在嗎？我需要一個 IP」（廣播）        │
    ├───────────────────────────────────────────▶│
    │                                            │
    │  ②「給你 192.168.1.105，租期 7 天」         │
    │◀───────────────────────────────────────────┤
    │                                            │
    │  ③「好，我要這個」                          │
    ├───────────────────────────────────────────▶│
    │                                            │
    │  ④「成交」                                 │
    │◀───────────────────────────────────────────┤
```

英文縮寫是 **DORA**：Discover → Offer → Request → Acknowledge。

排查時看到的 `DHCP timeout`，就是這個對話在某一步卡住了。

### 一個網路只能有一個 DHCP 伺服器

這是把路由器改成交換器時**一定要關 DHCP** 的原因：

```
       ❌ 兩個都在發
   ┌─────────┐        ┌─────────┐
   │ 路由器A │        │ 路由器B │
   │  DHCP   │        │  DHCP   │
   └────┬────┘        └────┬────┘
        └────────┬─────────┘
                 ▼
           「我需要 IP！」
                 │
        誰快誰贏，而且兩邊
        發的號碼互不知情
                 │
                 ▼
            遲早撞號
```

症狀是**時好時壞、極難排查** —— 因為每次開機拿到誰發的 IP 是隨機的。

### 靜態 IP 要避開 DHCP 池

手動指定的位址一定要在 DHCP 發放範圍**外面**，否則伺服器哪天把同一個號碼發給別人就撞號了。

判斷方法：看實際發出去的位址。如果現有裝置都拿到 `.100` 開頭，那池大概是從 `.100` 起跳，`.2` 就安全。不確定就進路由器管理頁看設定。

## 七、DNS — 網址簿

上一章的 DHCP 解決「我是誰」。這一章的 DNS 解決「**別人叫什麼**」。

你的裝置不認得 `google.com`，只認得 IP。DNS 就是把名字翻成位址的網址簿。

### 一次查詢實際上發生什麼

```
你的裝置              解析器 Resolver              權威伺服器們
   │              （ISP 的 / 8.8.8.8 / NextDNS）
   │  google.com 的 IP?      │
   ├────────────────────────▶│
   │                         │ 問根伺服器：「.com 去問誰？」──▶
   │                         │ 問 .com 伺服器：「google.com 誰管？」──▶
   │                         │ 問 google 的權威伺服器：「142.251.x.x」
   │   142.251.x.x           │
   │◀────────────────────────┤ （順便存進快取）
   │
   └──── 拿到 IP，直接連過去 ────▶ 網站
```

注意**你的裝置只問了一次**，後面那串接力是解析器代勞的。這叫**遞迴查詢**，解析器也因此叫「遞迴解析器」。

查到的結果會被快取一段時間，長度由網域擁有者設定的 **TTL** 決定。這就是為什麼改了 DNS 記錄不會立刻生效 —— 全世界的快取要等各自的 TTL 到期。

### 解析器看得到你查過的每一個網域

這是 DNS 最常被忽略的隱私問題。

預設的解析器是 ISP 的，所以**中華電信知道你連過哪些網站** —— 就算網站本身是 HTTPS 也一樣，因為加密保護的是內容，不是「你問了哪個名字」這件事。

```
   傳統 DNS（明文）
   你 ──「google.com 的 IP?」──▶ 解析器
        ▲
    這句話沿路的人都看得到
```

**DoH / DoT**（DNS over HTTPS / over TLS）把查詢本身也加密：

```
   加密 DNS
   你 ═══加密═══▶ 解析器
        ▲
    ISP 只知道「你在跟某個解析器講話」
    不知道你問了什麼
```

代價是**信任轉移**：ISP 看不到了，但你選的那家解析器看得到。換掉 ISP 的解析器不等於沒人看得到，只是換一個對象。

### DNS 攔截：在查號台就說「查無此號」

NextDNS、Pi-hole、AdGuard DNS 這類服務，本質就是**一台加了黑名單的解析器**：

```
   │  ads.doubleclick.net 的 IP?  │
   ├─────────────────────────────▶│  比對黑名單 → 命中
   │   查無此網域 / 0.0.0.0        │
   │◀─────────────────────────────┤
   │
   └─ 連不上 → 廣告的請求根本沒送出去
```

因為攔在**查名字**這一步，廣告的連線從頭到尾沒有建立 —— 省流量、省電、也省掉被追蹤的機會。

而且它管的是**整台裝置**，不只瀏覽器。手機遊戲、電視盒、智慧家電這些裝不了瀏覽器擴充功能的地方，DNS 是唯一能下手的位置。

> 設定的位置決定覆蓋範圍：設在**路由器**上，全家所有裝置一次搞定，但看不出是誰查的；設在**單一裝置**上，只保護那台，但帶著走。

DNS 攔截也有它做不到的事 —— 下一章會跟其他工具一起比較。

---

## 八、NAT — 共用一個對外身分

**一句話：把一個公網 IP 分給很多台裝置共用。**

IPv4 位址只有約 43 億個，全球早就不夠分。ISP 給你的是**一個**對外 IP，但家裡有筆電、手機、平板、電視、樹莓派⋯⋯

NAT（Network Address Translation）的做法是在路由器上維護一張翻譯表：

```
        內部（私有）                對外（公有）                  目的地
   ┌─────────────────────┐   ┌──────────────────────┐   ┌──────────────┐
   │ 192.168.1.105:6973  │◀─▶│ 114.36.x.x:51001     │──▶│ 1.1.1.1:443  │
   │ 192.168.1.107:5120  │◀─▶│ 114.36.x.x:51002     │──▶│ 8.8.8.8:443  │
   │ 192.168.1.110:8891  │◀─▶│ 114.36.x.x:51003     │──▶│ 142.251.x:443│
   └─────────────────────┘   └──────────────────────┘   └──────────────┘
          你家裡                  對外界只有這一個 IP
```

封包出去時，路由器把來源位址改成自己的公網 IP 加一個沒用過的埠號，記進表裡。回應回來時查表改回去，送給正確的裝置。

**對外界來說，你家只有一台機器在上網。**

### NAT 的根本不對稱

這是理解後面所有問題的關鍵：

```
由內向外 ──▶  封包出去的瞬間「自動建立」表項目  ──▶  回應找得到路  ✅

由外向內 ──▶  表裡沒有對應項目                ──▶  不知道該給誰  ❌
                                                     只能丟掉
```

所以「你連出去」永遠沒問題，「別人連進來」預設永遠不通。

> 順帶一提：NAT 常被當成防火牆，但它**不是**。它擋住外面只是副作用，不是設計目的。

## 九、連接埠轉發 — 讓外面找到你

既然外來連線找不到人，就**手動在表裡預先寫一條規則**。

我自己的例子是開 Terraria 伺服器給朋友連。獨立伺服器 `TerrariaServer.exe` 監聽 7777 埠，朋友要從外面連進來：

```
   朋友                路由器                        我的電腦
     │                   │                              │
     │  連 我的公網IP:7777 │                              │
     ├──────────────────▶│                              │
     │                   │  查「連接埠轉發」規則：        │
     │                   │  7777 ──▶ 192.168.1.110:7777 │
     │                   ├─────────────────────────────▶│
     │                   │                              │  TerrariaServer.exe
     │◀──────────────────┼◀─────────────────────────────┤  正在監聽
```

實務上還要處理兩件事：

1. **公網 IP 會變** — 家用寬頻多半是浮動 IP。用 DuckDNS 這類動態 DNS 服務綁一個固定網址，它會定期回報你當下的 IP
2. **防火牆是另一關** — 路由器放行 ≠ 電腦放行。`TerrariaServer.exe` 跟遊戲本體 `Terraria.exe` 是不同執行檔，Windows 防火牆規則要**重新放行一次**

完全不想碰路由器設定的話，還有一條完全不同的路 —— 用 [Tailscale](https://tailscale.com/) 這類 mesh VPN 讓雙方裝置像在同一個區網裡，整個繞過 NAT。**這個做法在第十一章單獨講。**

## 十、雙重 NAT 會出什麼問題

當你有兩台路由器串在一起：

```
外面 ──▶ 路由器A [NAT #1] ──▶ 路由器B [NAT #2] ──▶ 你的裝置
           192.168.1.x           192.168.0.x
```

### 1. 連接埠轉發要設兩次

```
外面:7777 ──▶ 路由器A ──▶ 路由器B ──▶ 你的電腦
              要設一條    還要設一條
```

漏掉任何一層就不通，而第二層的存在很容易被忘記。

### 2. 自動開埠機制會失效

UPnP / NAT-PMP 讓應用程式自己跟路由器要一個埠（遊戲、BT、視訊常用）。但它只會跟**最近的那台**講 —— 內層開了，外層不知道，等於白開。

### 3. P2P 打洞成功率下降

視訊通話、遊戲連線、WebRTC 靠 STUN 打洞：雙方同時往外送封包，在各自的 NAT 上撞出一條通路。多一層 NAT，埠號多一次映射，對方猜不到你的真實埠號 —— 打洞失敗就退回中繼伺服器，延遲變高、畫質變差。

### 4. 有些協定會把 IP 寫在封包內容裡

FTP 主動模式、SIP（網路電話）會在**內容**裡夾帶自己的 IP。NAT 只改標頭改不到內容，要靠 ALG 特別處理。兩層各改一次，很容易改壞。

### 5. 裝置互相看不見（最有感的一點）

```
   路由器A ── 印表機、電視        192.168.1.x  ┐
      │                                        ├─ 這兩群
      └─ 路由器B ── 手機、筆電    192.168.0.x  ┘   彼此連不到
```

而且 AirPlay、Chromecast、印表機探索、mDNS 全都靠**廣播**，而廣播封包**不會跨越路由器**。於是出現「手機找不到印表機」「投影投不出去」這類靈異現象。

### 6. 排查地獄

兩層網路疊在一起，症狀會互相掩蓋。光是分辨「這個 IP 到底是誰、封包走哪條路」就要花掉大半時間。

## 十一、Tailscale — 繞過整個問題

前面兩章講的是「**正面突破**」—— 在 NAT 上開一個洞，讓外面連得進來。麻煩之處在於要設轉發、要 DDNS、雙重 NAT 還要設兩次。

還有另一條路：**根本不從外面連進來**，而是讓雙方都往外連，在中間會合。

### 核心想法：利用 NAT 的不對稱

還記得第八章那個不對稱嗎 —— **由內向外永遠暢通，由外向內預設不通**。

Tailscale 做的事就是：**讓兩邊同時往外送封包**，各自在自己的 NAT 上撞出一個洞，然後從那兩個洞接起來。

```
   你（NAT-A 後面）                     朋友（NAT-B 後面）
        │                                    │
        │ ① 兩邊都先連上協調伺服器            │
        ├───────────▶ 協調伺服器 ◀───────────┤
        │            （Tailscale 的）         │
        │                 │                  │
        │ ② 伺服器告訴雙方對方的公網 IP:Port  │
        │◀────────────────┴─────────────────▶│
        │                                    │
        │ ③ 兩邊「同時」往對方送 UDP 封包      │
        ├───────────────╳───────────────────▶│
        │◀──────────────╳────────────────────┤
        │                                    │
        │   各自的 NAT 看到「這是我送出去的」  │
        │   → 自動建立翻譯表項目              │
        │   → 對方的封包回來時就對得上了       │
        │                                    │
        │ ④ 之後直接點對點通訊，不經過伺服器   │
        │◀══════════════════════════════════▶│
```

這叫 **UDP 打洞（hole punching）**。重點是第 ③ 步的「同時」—— 誰先送出去，誰的 NAT 就先建立好項目，另一邊的封包才進得來。協調伺服器的工作就是讓兩邊對好時間。

### 控制平面與資料平面是分開的

這是 Tailscale 架構上最重要的一點，也是它跟傳統 VPN 最大的差別。

```
   ┌─────────── 控制平面 ───────────┐
   │  Tailscale 的協調伺服器         │
   │  · 保管每台裝置的「公鑰」        │
   │  · 告訴大家彼此的連線端點        │
   │  · 執行存取規則（ACL）          │
   │                                │
   │  ✗ 看不到你傳的內容             │
   └────────────────────────────────┘

   ┌─────────── 資料平面 ───────────┐
   │  你的裝置 ◀══════▶ 對方的裝置   │
   │  用 WireGuard 加密，點對點直連   │
   │                                │
   │  ✗ 不經過 Tailscale 的伺服器    │
   └────────────────────────────────┘
```

底層的加密隧道用的是 **WireGuard** —— 現代、輕量、速度快的 VPN 協定。每台裝置有自己的公私鑰對，**私鑰永遠不離開那台裝置**。協調伺服器只經手公鑰，所以就算它被入侵，也解不開你的流量。

傳統 VPN 是**中心輻射式**：所有流量先繞到 VPN 伺服器再轉出去。Tailscale 是**網狀**：能直連就直連。

### 打不通的時候：DERP 中繼

有些 NAT 特別難搞（對稱型 NAT、CGNAT、企業防火牆），洞打不出來。這時 Tailscale 會退回**中繼模式**：

```
   你 ──▶ DERP 中繼伺服器 ──▶ 朋友
           （全球多個節點）

   中繼看到的是加密後的亂碼
   它只負責轉發，解不開內容
```

DERP = Designated Encrypted Relay for Packets。它是**保底方案**，代價是延遲變高（要繞一趟）。

Tailscale 會持續嘗試升級成直連，所以常見的情況是「剛連上時走中繼，幾秒後自動切成直連」。

### 100.x 的位址與 MagicDNS

每台加入的裝置會拿到一個 `100.x.y.z` 的位址，來自 `100.64.0.0/10` 這個保留網段。

**這個位址不會變** —— 不管你在家、在學校、還是用手機熱點。這點很關鍵，等於免費的固定 IP，只是只有你的 tailnet 裡認得。

MagicDNS 再往上加一層，讓你可以直接用機器名稱連，不用記位址。

### 為什麼 Terraria 用它比較穩

對照一下兩種做法：

| | 連接埠轉發 + DDNS | Tailscale |
|---|---|---|
| 要設路由器 | 要，雙重 NAT 還要設兩層 | **不用** |
| 對外位址會變 | 會，所以需要 DDNS | **不會，100.x 固定** |
| ISP 用 CGNAT 時 | **完全沒救**，你沒有自己的公網 IP | 照常運作 |
| 伺服器暴露在公網 | 是，任何人都掃得到 | **否，只有授權的人看得到** |
| 朋友要裝東西 | 不用 | **要裝 Tailscale** |
| 延遲 | 直連，最低 | 直連時相近；走中繼時較高 |

那次會改用 Tailscale，很可能是因為當時還是**雙重 NAT** —— 兩層 NAT 讓連接埠轉發要設兩次、打洞成功率也下降。Tailscale 把整個問題繞過去了。

朋友連線方式從 `你的DDNS網址:7777` 變成 `100.x.y.z:7777`，遊戲端一樣是「透過 IP 加入」。

> 實務提醒：**Windows 防火牆仍然要放行**。Tailscale 介面對防火牆來說是一張新網卡，伺服器程式要在那張介面上被允許，否則封包到得了電腦卻進不了程式。

### 分享單台機器（Sharing）

這是那次實際用到的功能。你**不需要**把朋友加進自己的 tailnet（那會讓他看到你所有裝置），只要分享**那一台**：

```
   你的 tailnet                     朋友的 tailnet
   ┌──────────────┐                ┌──────────────┐
   │ 筆電          │                │ 他的電腦      │
   │ 手機          │                │ 他的手機      │
   │ 遊戲主機 ●────┼───── 分享 ─────┼──▶ 看得到這台 │
   │ NAS          │                │              │
   └──────────────┘                └──────────────┘
        ▲                                  ▲
   他看不到這些                      你也看不到他的
```

對方收到邀請、接受之後，那台機器就出現在他的裝置清單裡，其他的完全隔離。**這比開連接埠轉發安全得多** —— 轉發是對全世界開門，分享是對特定的人開門。

### 其他值得知道的功能

| 功能 | 作用 |
|---|---|
| **Subnet router** | 讓一台裝置把**整個區網**（例如 `192.168.1.0/24`）帶進 tailnet，其他裝置不用各自安裝就能連 |
| **Exit node** | 把所有對外流量都繞經某台裝置，等於傳統 VPN 的用法 |
| **ACL** | 用設定檔定義誰能連誰的哪個埠 |
| **Taildrop** | 裝置之間直接傳檔 |

Subnet router 對家用特別實用 —— 在家裡放一台常開的機器（樹莓派之類）當 subnet router，在外面就能連回家裡**所有**裝置，包括不能安裝 Tailscale 的印表機、NAS、IP 攝影機。

### 代價與替代方案

- **依賴第三方協調伺服器**。不想依賴的話有 **Headscale**（開源的自架控制平面）
- **每台裝置都要安裝**，所以不適合「給不特定多數人連」的公開服務
- 同類產品還有 **ZeroTier**、**NetBird**，原理相近

## 十二、擋廣告與隱私工具的差別

擋廣告、保護隱私的工具常被混為一談，但它們作用在**完全不同的層級**，而且互不取代。

### DNS 攔截 vs 瀏覽器 Adblocker

| | DNS 攔截（NextDNS 等） | Adblocker（uBlock 等） |
|---|---|---|
| 在哪運作 | 網路層，查名字的時候 | **瀏覽器裡面**，頁面渲染的時候 |
| 看得到什麼 | 只有**網域名稱** | 完整網址、頁面元素、腳本內容 |
| 管得到誰 | **整台裝置的所有 app** | 只有那個瀏覽器 |
| 精細度 | 整個網域封鎖或放行 | 可以只擋某個路徑、某個元素 |
| 版面 | 會留下空白 | 可以把空間一起收掉 |

#### 關鍵差異：同網域的廣告 DNS 擋不掉

YouTube 是最好的例子。影片和廣告**都來自同一個網域**。

```
   DNS 看到的：  googlevideo.com   ← 只有這個
                   擋 → 影片也沒了
                   放 → 廣告也進來了

   Adblocker 看到的：
       googlevideo.com/videoplayback?...&ad=1   ← 擋這個
       googlevideo.com/videoplayback?...        ← 放這個
```

DNS 只知道名字，不知道後面的路徑和參數，**在同一個網域內無法區分**。這就是為什麼純 DNS 方案擋不掉 YouTube 廣告。

反過來，DNS 能做到 adblocker 做不到的事：**擋掉 app 和非瀏覽器裝置的廣告與追蹤**。

> 所以正確答案是**兩個一起用**：DNS 負責全裝置的粗篩，adblocker 負責瀏覽器裡的精修。

### VPN 到底在做什麼

「讓位置變假」是**副作用，不是目的**。

VPN 真正做的事：**把你的所有流量加密，塞進一條隧道，從別的地方出去。**

```
   沒有 VPN：
   你 ──▶ ISP（看得到你連哪）──▶ 網站（看到你的真實 IP）

   有 VPN：
   你 ═══加密隧道═══▶ VPN 伺服器 ──▶ 網站
        │                  │
    ISP 只看到           網站看到的是
   「一堆加密流量         VPN 伺服器的 IP
    送去某個伺服器」      → 所以「位置變了」
```

VPN 這個詞原本的意思是**安全地遠端接回公司內網**，企業界至今仍是這個用法。消費級 VPN 是把同一個技術拿來做跨區解鎖和隱私。

**有效**：ISP 看不到你連哪些網站、公共 Wi-Fi 上竊聽不到、網站看不到你的真實 IP。

**無效**：

- **不等於匿名**。你登入 Google 帳號，Google 照樣知道你是誰。Cookie 和瀏覽器指紋都還在
- **信任只是轉移**。原本 ISP 看得到的，現在 VPN 業者看得到，而且他們通常沒有電信法規的約束

#### 「VPN 也能擋廣告」是怎麼回事

因為很多 VPN app **順便內建了一個 DNS 過濾器**。

擋廣告的是那個 DNS 過濾功能，**跟 VPN 本身沒有關係**。把 VPN 關掉只留 DNS 設定，一樣擋得掉。

### 防火牆完全不是同一回事

防火牆**不看內容**，它看的是連線本身：

| 防火牆判斷的 | 例子 |
|---|---|
| 來源 / 目的 IP | 擋掉某個位址段 |
| 埠號 | 只開放 443，其他全關 |
| 方向 | 允許出去，擋掉進來 |
| 哪個程式 | `TerrariaServer.exe` 可以聽網路 |

它管的是**「這條連線准不准建立」**，不管裡面傳什麼。所以防火牆**擋不了廣告** —— 廣告和正常內容走的是同一個 443 埠、同一條 HTTPS 連線。

### 一個類比把四個串起來

```
   防火牆     = 大樓警衛
                看你從哪來、要去幾樓，決定放不放行
                不看你手上拿什麼

   DNS 攔截   = 查號台
                你問「廣告公司電話幾號」
                它說「查無此號」，你就打不出去

   Adblocker  = 你請的秘書
                信件拆開後，把裡面的廣告夾頁撕掉再給你
                只服務你這個房間

   VPN        = 請人代收轉寄
                所有信先寄到代收處，再由他轉給你
                外界只看得到代收處的地址
```

### 作用層級對照

```
   ┌─────────────────────────────────────┐
   │  Adblocker    看得到頁面內容         │  最精細，範圍最小
   ├─────────────────────────────────────┤
   │  DNS 攔截     看得到網域名稱         │  全裝置，但只能整域封鎖
   ├─────────────────────────────────────┤
   │  防火牆       看得到 IP / 埠 / 程式  │  管通不通，不管內容
   ├─────────────────────────────────────┤
   │  VPN          把整條路加密改道       │  不過濾，只改變路徑和可見性
   └─────────────────────────────────────┘
```

**它們互不取代。** 「DNS 攔截 + 瀏覽器 adblocker」是覆蓋面最好的日常組合；VPN 解決的是另一個問題（誰看得到你的流量），防火牆解決的又是另一個（誰連得進來）。

## 十三、四者怎麼串起來

```
   你插進 LAN 孔
         │
         ▼
   ① DHCP 給你一個內部 IP        ──▶  你有門牌了
         │
         ▼
   ② 你連 google.com
         │
         ▼
   ③ NAT 把來源改成公網 IP        ──▶  出得去，回得來
         │
         ▼
   ④ 別人想連你？表裡沒資料       ──▶  被丟掉
         │
         ▼
   ⑤ 除非你設了連接埠轉發          ──▶  進得來
```

- **DHCP** 解決「我是誰」
- **NAT** 解決「怎麼共用一個對外身分」
- **連接埠轉發** 解決「怎麼讓外面找到我」
- **WAN/LAN** 定義「哪邊算外面」

## 十四、IPv6 不需要 NAT

IPv6 有 `2^128` 個位址，多到每台裝置都能分到一個全球唯一的位址。不需要共用，**自然就不需要翻譯**。

安全性改由防火牆負責 —— 這其實才是正確的做法，因為「擋住外來連線」本來就該是防火牆的職責，用 NAT 順便達成只是歷史的將就。

所以 NAT 本質上是 **IPv4 位址不夠用的補丁**，只是這個補丁打了三十年，大家都習慣了。

## 附錄 A：容易搞混的名詞

自我檢查用。每一組都附「一句話辨別法」。

### 1. 數據機 vs 路由器

- **數據機（Modem / ONT）**：轉換訊號。電話線或光纖 ◀▶ 乙太網路
- **路由器（Router）**：轉發封包、做 NAT、發 DHCP

> 辨別法：數據機只有一個對外孔加一個對內孔；路由器有 WAN 加好幾個 LAN。

### 2. 集線器 vs 交換器 vs 路由器

```
集線器 Hub     收到封包 ──▶ 無腦複製給所有孔        （已絕跡）
交換器 Switch   收到封包 ──▶ 查 MAC 表，只給正確那個孔
路由器 Router   收到封包 ──▶ 查路由表，跨網段轉發
```

> 辨別法：交換器管**同一個網段內**，路由器管**網段之間**。

### 3. IP vs MAC

- **MAC**：燒在網卡上的實體位址。**跟你在哪裡無關**，走到天涯海角都一樣
- **IP**：邏輯位址，**由你目前在哪個網路決定**。換個網路就換一個

> 類比：MAC 是身分證字號，IP 是現在住的地址。搬家地址會變，身分證字號不會。
> 辨別法：同一個網段內找人靠 MAC（ARP 在做的事），跨網段找人靠 IP。

### 4. 撥接 / PPPoE 不是訊號轉換

這兩件事常被混在一起，但由不同角色負責：

- **訊號轉換**是**數據機**做的
- **撥接 / PPPoE** 是**認證程序** — 拿帳密跟 ISP 說「我是付錢的用戶，給我一個公網 IP」

> 證據：ONT 走光纖不是電話線，但一樣要 PPPoE 撥號。

### 5. NAT vs DHCP

最常被混淆的一組，因為兩者都跟 IP 有關。

- **DHCP** 發的是**內部門牌** — 自動把 IP 租給來要的裝置，有租期
- **NAT** 管的是**對外身分** — 讓多台共用一個公網 IP，靠改寫封包的位址和埠號

> 辨別法：DHCP 在你家內部運作，NAT 在你家對外的邊界運作。
> NAT 不「分配」IP，它「改寫」封包。

### 6. 靜態 IP vs DHCP 保留

結果都是「這台每次都拿到同一個 IP」，但機制完全不同。

| | 誰決定 | 設在哪 |
|---|---|---|
| **靜態 IP** | 裝置自己 | 裝置的網路設定裡 |
| **DHCP 保留** | 伺服器 | 路由器的 DHCP 設定裡，綁 MAC |

> 關鍵差異：靜態 IP 的裝置**不參與 DHCP**，伺服器不知道那個號碼被用掉了。
> 所以**靜態 IP 一定要設在 DHCP 池外面**。DHCP 保留沒這問題。

### 7. 固定 IP（公網）vs 靜態 IP（私網）

中文都叫「固定」，但層次完全不同。

```
         對外（ISP 給的身分）            對內（自家門牌）
   ┌──────────────────────────┐  ┌──────────────────────────┐
   │  浮動 IP  ← 家用預設      │  │  DHCP 自動取得 ← 一般裝置  │
   │  固定 IP  ← 付費申請      │  │  靜態 IP  ← 手動指定       │
   └──────────────────────────┘  └──────────────────────────┘
        全球唯一，要錢                私有網段，免費
```

商用固定 IP 通常給一整段（例如 8 個，實用 5 個），意義在於**每台伺服器可以各拿一個公網 IP，不用經過 NAT** — 這樣兩台伺服器就能同時用 80 埠，在單一 IP 加 NAT 底下辦不到。

> **DDNS（DuckDNS 那類）是浮動 IP 的窮人版固定 IP。** 它讓網址不變，背後指向會變的 IP。
> 注意：有固定 IP 不代表不用設連接埠轉發。只要還在 NAT 後面，轉發照樣要設。

### 8. WAN 側取得 IP 的三種方式

| 方式 | 什麼時候用 |
|---|---|
| **PPPoE** | 要帳號密碼認證，台灣家用寬頻最常見 |
| **DHCP** | 上游自動發給你 |
| **手動靜態** | ISP 給固定 IP，要自己填 IP、遮罩、閘道 |

> 這解釋了為什麼路由器**沒辦法自動偵測雙重 NAT**：
> 「WAN 孔收到 DHCP」是完全正常的狀態，不是異常訊號。
> 真正的訊號是「**WAN IP 落在私有網段**」。

### 9. 公網 IP vs 私有 IP

私有網段有三塊，是 RFC1918 規定的，**全世界的路由器都同意不轉發它們**：

```
10.0.0.0     ~ 10.255.255.255      （大型）
172.16.0.0   ~ 172.31.255.255      （中型）
192.168.0.0  ~ 192.168.255.255     （家用，最常見）
```

> 實用技巧：路由器的 WAN IP 如果落在這三塊裡，就代表**你在雙重 NAT 底下**。這是最快的判斷法。

### 10. 閘道 vs DNS 伺服器

- **閘道（Gateway）**：要出這個網段時，封包交給誰。通常是路由器
- **DNS**：把網域名稱翻譯成 IP 的服務

> 辨別法：閘道管**路怎麼走**，DNS 管**目的地叫什麼**。
> 「網路通但網頁開不了」通常是 DNS 壞了 — 因為 ping IP 會通、ping 網址不會。

### 11. 埠（Port）的兩種意思

中文都叫「埠」，但完全是兩回事：

- **實體埠**：路由器上的 RJ45 孔，`LAN 1`、`WAN`
- **TCP/UDP 埠號**：軟體層的編號，`7777`、`443`、`80`

> 連接埠轉發轉的是**埠號**，不是實體孔。

### 12. AP vs 中繼器 vs Mesh 節點

- **AP**：有線接回主機，把有線變無線。**不損失頻寬**
- **中繼器（Repeater / Extender）**：用無線接收再用無線轉發，**頻寬直接砍半**
- **Mesh 節點**：進化版中繼器，多了節點間協調和無縫漫遊

> 辨別法：看它**怎麼接回主機**。有線就是 AP，無線就是中繼。

### 13. 連線速率 vs 實際吞吐量

- **連線速率（Link rate）**：網卡協商出來的數字
- **吞吐量（Throughput）**：實際傳得多快

Wi-Fi 的協商速率**永遠是理論值**，實際大概打對折甚至更低（共享介質、重傳、干擾）。有線的協商速率則接近實際值。

> 所以 Wi-Fi 顯示 115 Mbps、有線顯示 100 Mbps 時，實際上**有線還是快得多**。

### 14. 傳統 VPN vs Mesh VPN

- **傳統 VPN**：中心輻射式。所有流量先繞到 VPN 伺服器，再從那裡轉出去
- **Mesh VPN**（Tailscale、ZeroTier…）：網狀。**能直連就直連**，伺服器只負責牽線

```
   傳統 VPN                   Mesh VPN
   ─────────                  ────────
   A ──▶ 伺服器 ──▶ B          A ◀════▶ B   （直連）
        （所有流量）                ▲
                              協調伺服器只交換公鑰
                              看不到流量內容
```

> 辨別法：看**流量走哪裡**。傳統 VPN 的伺服器在資料路徑上，Mesh VPN 的協調伺服器不在。
> Mesh VPN 打不通時會退回中繼（DERP），那時才比較像傳統 VPN，但內容仍然是端到端加密的。

### 15. DNS 攔截 vs Adblocker vs 防火牆 vs VPN

四個常被混為一談，但層級完全不同。

| | 看得到什麼 | 管得到誰 | 擋廣告？ |
|---|---|---|---|
| **Adblocker** | 頁面內容、元素、完整網址 | 只有那個瀏覽器 | ✅ 最精準 |
| **DNS 攔截** | 只有網域名稱 | 整台裝置所有 app | ✅ 但同網域擋不掉 |
| **防火牆** | IP、埠號、方向、程式 | 整台裝置 | ❌ 不看內容 |
| **VPN** | 不過濾，只加密改道 | 整台裝置 | ❌ 內建的 DNS 過濾器才會 |

> 辨別法：**防火牆管「准不准連」，DNS 管「找不找得到」，adblocker 管「顯不顯示」，VPN 管「誰看得到」**。
> 它們互不取代。

### 16. 頻寬 vs 延遲

- **頻寬**：管子多粗，單位 Mbps。決定**一次能搬多少**
- **延遲**：跑一趟多久，單位 ms。決定**反應多快**

> 兩者獨立。衛星網路可以有 100 Mbps 頻寬但 600ms 延遲。
> 打遊戲在乎延遲，下載在乎頻寬。

## 附錄 C：英文縮寫對照表

縮寫最容易搞混的不是意思，是**類別** —— 先分清楚一個詞講的是公司、技術、設備，還是協定。

```
   公司   ISP                      誰賣你網路
   技術   ADSL / VDSL / GPON       用什麼方式傳
   設備   ONT / Router / Switch    哪一台機器
   協定   PPPoE / DHCP / DNS       機器之間怎麼講話
```

`ADSL` 和 `ONT` 不是同類的東西：前者是「怎麼傳」，後者是「哪台機器」。

### 公司與角色

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **ISP** | Internet Service Provider | 網路服務供應商。中華電信、遠傳這些**公司** |
| **CPE** | Customer Premises Equipment | 裝在用戶家裡的設備總稱。小烏龜、路由器都算 |

### 最後一哩的傳輸技術

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **DSL** | Digital Subscriber Line | 用**電話銅線**傳資料的技術家族 |
| **ADSL** | **A**symmetric DSL | 非對稱 DSL。「非對稱」指**下載比上傳快** |
| **VDSL** | Very-high-bit-rate DSL | ADSL 的加速版，距離較短 |
| **PON** | Passive Optical Network | 被動光纖網路。「被動」指分光器**不用電** |
| **GPON** | Gigabit-capable PON | 目前台灣光纖的主流架構 |
| **FTTH** | Fiber To The Home | 光纖直接拉到你家 |
| **FTTB** | Fiber To The Building | 只拉到大樓，樓內走銅線 |

### 線路兩端的設備

每個世代都有一組「你家那台」對「機房那台」，命名邏輯完全一樣。

| 世代 | 用戶端 | 局端 |
|---|---|---|
| **ADSL** | **ATU-R**（ADSL Transmission Unit - **R**emote） | **ATU-C**（- **C**entral）／**DSLAM** |
| **光纖** | **ONT / ONU** | **OLT** |

| 縮寫 | 全稱 | 在哪一端 |
|---|---|---|
| **OLT** | Optical Line Terminal | **機房端**，電信公司那頭 |
| **ONT** | Optical Network Terminal | **用戶端**，你家那台 |
| **ONU** | Optical Network Unit | 幾乎等於 ONT。習慣上 ONT 指單戶、ONU 有時指多戶共用 |
| **ATU-R** | ADSL Transmission Unit - Remote | ADSL 時代的「你家那台」，就是 ADSL 數據機 |
| **DSLAM** | DSL Access Multiplexer | 機房裡把幾百條電話線匯集起來的設備，OLT 的前身 |

> 記法：**`-R` 是遠端（你家）、`-C` 是中央（機房）**，跟 ONT 對 OLT 是同一組配對關係。

### 「數據機」這個詞

**Modem** = **Mo**dulator + **Dem**odulator，調變器加解調器。本業是**把數位訊號調變成適合那個介質傳輸的形式，到對面再解調回來**。

介質不同就是不同的 modem：

| 介質 | 設備 |
|---|---|
| 電話線（語音頻段） | 撥接數據機（56k） |
| 電話線（高頻段） | ADSL 數據機 = ATU-R |
| 同軸電纜（第四台） | Cable modem |
| 光纖 | **ONT / ONU** |

> 為什麼光纖那台不叫 modem？因為它主要做**光電轉換**，而不是把訊號調變到類比載波上，所以用 **Terminal（終端設備）** 命名。
> 口語上大家還是照叫數據機 —— 中華電信的用戶更是不管哪一代都叫它**小烏龜**，那個綽號本來是講 ADSL 那台的機殼形狀，換成光纖後就沿用了。

### 取得連線與位址

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **PPPoE** | Point-to-Point Protocol over Ethernet | 用帳密向 ISP 認證並取得對外 IP |
| **DHCP** | Dynamic Host Configuration Protocol | 自動發 IP 的服務 |
| **DORA** | Discover / Offer / Request / Acknowledge | DHCP 的四步握手 |
| **NAT** | Network Address Translation | 多台裝置共用一個公網 IP |
| **CGNAT** | Carrier-Grade NAT | ISP 自己也做一層 NAT，用戶連公網 IP 都沒有 |

### 命名

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **DNS** | Domain Name System | 把網址翻譯成 IP |
| **DoH** | DNS over HTTPS | 加密的 DNS 查詢 |
| **DoT** | DNS over TLS | 同上，走不同的埠 |
| **mDNS** | multicast DNS | 區網內的裝置自我介紹，AirPlay 之類靠它 |
| **SSDP** | Simple Service Discovery Protocol | 區網內找裝置用，Chromecast 之類靠它 |

> ⚠️ **TTL 有兩個完全不同的意思**
> · 在 **DNS** 裡是「這筆快取可以留多久」，單位是秒
> · 在 **IP 封包**裡是「還能再經過幾台路由器」，每跳減一，歸零就丟掉
> `tracert` 正是靠第二種 TTL 運作的：故意把 TTL 設成 1、2、3⋯，逼沿路每一台路由器回報自己是誰。

### 網際網路的骨架

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **AS** | Autonomous System | 自治系統。一個獨立管理的網路，有自己的編號 |
| **BGP** | Border Gateway Protocol | AS 之間互相宣告「我能到達哪些網段」 |
| **IXP** | Internet Exchange Point | 網際網路交換中心，多家 ISP 在此互連 |
| **IANA** | Internet Assigned Numbers Authority | 全球位址與編號的最高分配機構 |
| **RIR** | Regional Internet Registry | 區域註冊管理機構，向 IANA 領位址再分下去 |
| **APNIC** | Asia-Pacific Network Information Centre | 亞太區的 RIR，台灣屬於它 |
| **RFC** | Request for Comments | 網路標準文件的格式。RFC1918 就是定義私有網段那份 |

### 穿越 NAT

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **STUN** | Session Traversal Utilities for NAT | 幫你問出「我在 NAT 外面長什麼樣」 |
| **UPnP** | Universal Plug and Play | 讓程式自己跟路由器要一個埠 |
| **NAT-PMP** | NAT Port Mapping Protocol | 同上，Apple 提的版本 |
| **ALG** | Application-Level Gateway | 路由器幫忙修改封包**內容**裡的 IP |
| **DERP** | Designated Encrypted Relay for Packets | Tailscale 打洞失敗時的中繼 |

### 區網與無線

| 縮寫 | 全稱 | 意思 |
|---|---|---|
| **LAN / WAN** | Local / Wide Area Network | 對內 / 對外 |
| **AP** | Access Point | 無線基地台。把有線變無線 |
| **SSID** | Service Set Identifier | Wi-Fi 的**名字** |
| **BSSID** | Basic SSID | 那台 AP 的無線網卡 **MAC**。同一個 SSID 可以有多個 BSSID |
| **MAC** | Media Access Control | 燒在網卡上的實體位址 |
| **ARP** | Address Resolution Protocol | 在區網內用 IP 問出對應的 MAC |
| **VPN** | Virtual Private Network | 加密隧道 |
| **RJ45** | Registered Jack 45 | 網路線接頭的規格名稱 |

### 不是這裡的東西

| 縮寫 | 全稱 | 為什麼會搞混 |
|---|---|---|
| **ISL** | Inter-Switch Link | Cisco 的 VLAN 傳輸協定，企業交換器在用。**跟 ISP 只差一個字母，但毫無關係** |
